## Лабораторная работа №5

**Тема**: «Контейнеризация и упаковка приложения. Доработка прототипа с учётом обновлённых бизнес-требований».

---

### 1. Цель работы

Освоение технологии контейнеризации и упаковки приложения для обеспечения воспроизводимой среды выполнения и упрощения развёртывания. Доработка прототипа в соответствии с обновлёнными бизнес-требованиями, зафиксированными при сдаче лабораторной работы №4.

---

### 2. Список обновлённых бизнес-требований

В результате сдачи ЛР №4 от заказчика поступил новый набор бизнес-требований к системе уведомлений об акциях и скидках:

| № | Требование | Способ проверки |
|---|---|---|
| 1 | Система должна предоставлять **сводную статистику по рассылкам**: сколько кампаний было отправлено и кому именно. | Эндпоинт `GET /stats` и CLI-режим `promo_notify --stats`. |
| 2 | Сводная статистика должна выводиться **прямо в терминал** сервера для оперативного контроля оператором. | Запрос `GET /stats` печатает агрегат в `stdout` контейнера; CLI-режим печатает в `stdout` процесса. |
| 3 | В сводке для каждой акции должно быть видно: какая акция, **скольким людям отправили**, **кому хотели отправить, но уведомления выключены** (номер в списке отписавшихся). | Группировка по полю `name` (название акции), отдельные счётчики `sent` / `skipped` и списки телефонов `sent_phones` / `skipped_phones`. |

Бизнес-требования реализованы поверх существующей модели данных (таблицы `campaigns` и `unsubscribed`) — без миграций схемы. Источником сведений о номерах с выключенными уведомлениями служит статус кампании `skipped`, который проставляется при попытке отправки на отписанный номер.

---

### 3. Тип приложения

Backend-приложение: **HTTP-сервис на C++17** на базе фреймворка Crow с CLI-режимом для административных операций.

| Характеристика | Значение |
|---|---|
| Язык / стандарт | C++17 |
| HTTP-фреймворк | Crow `v1.0+5` |
| База данных | SQLite 3 (файл-БД, монтируется томом) |
| Внешний API | smsaero.ru (REST, Basic-авторизация) |
| Порт | `18080` |
| Формат развёртывания | Docker-образ |

Приложение имеет два режима запуска:
- **Сервер** — запуск без аргументов: `/app/promo_notify`. Поднимает HTTP-сервис на порту 18080.
- **CLI** — запуск с флагом: `/app/promo_notify --stats`. Печатает сводную статистику в `stdout` и завершается.

### 4. Упаковка приложения

#### 4.1. Структура Dockerfile (оптимизированный, multi-stage)

```dockerfile
# syntax=docker/dockerfile:1.6

# ===== Builder =====
FROM ubuntu:22.04 AS builder
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
    cmake make g++ git ca-certificates \
    libboost-program-options-dev libboost-system-dev libboost-date-time-dev \
    libcurl4-openssl-dev libsqlite3-dev nlohmann-json3-dev libgtest-dev \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /build
COPY . .
RUN cmake -B build -DCMAKE_BUILD_TYPE=Release && \
    cmake --build build --parallel && \
    strip build/app/promo_notify && strip build/app/tests/promo_tests

# ===== Tester (промежуточная стадия для прогона тестов) =====
FROM builder AS tester
RUN /build/build/app/tests/promo_tests

# ===== Runtime =====
FROM ubuntu:22.04 AS runtime
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
    libboost-program-options1.74.0 libboost-system1.74.0 libboost-date-time1.74.0 \
    libcurl4 libsqlite3-0 sqlite3 \
    && rm -rf /var/lib/apt/lists/* /var/cache/apt/* /var/log/apt/* \
              /tmp/* /var/tmp/* \
    && find /usr/share/doc -depth -type f ! -name copyright -delete \
    && find /usr/share/doc -empty -delete \
    && rm -rf /usr/share/man/* /usr/share/locale/* /usr/share/info/*
RUN mkdir -p /data
WORKDIR /app
COPY --from=builder /build/build/app/promo_notify /app/promo_notify
EXPOSE 18080
CMD ["/app/promo_notify"]
```

Применённые приёмы оптимизации:
- **Multi-stage build** — тулчейн (cmake, g++, dev-пакеты) остаётся в стадии `builder` и не попадает в финальный образ.
- **`--no-install-recommends`** — отрезаются «рекомендованные» транзитивные пакеты.
- **`strip`** — снимает отладочные символы с бинарников (`promo_notify` уменьшается с ~1.6 MB до ~610 KB).
- **Чистка `/usr/share/{doc,man,locale,info}`** — экономит ~3 MB на текстовой документации, не нужной в продакшене.
- **`promo_tests` не копируется в финальный образ** — тестовый бинарник доступен только в стадии `tester`.
- **`.dockerignore`** — исключает из build-контекста `.git`, `*.pdf`, `*.docx`, `build/`, `*.db`, ускоряя сборку.

#### 4.3. Команды сборки и запуска

```bash
# Сборка оптимизированного образа
docker build -t promo_notify:latest .

# Запуск через docker compose
docker compose up -d --build

# Запуск unit-тестов (промежуточная стадия)
docker build --target tester -t promo_notify:test .

# Запуск CLI-режима для просмотра статистики
docker compose exec app /app/promo_notify --stats

# Просмотр статистики через HTTP API + сводка в терминал сервера
curl http://localhost:18080/stats
docker compose logs app
```

После `docker compose up -d --build` контейнер `promo-notify-cpp-app-1` отображается в Docker Desktop в статусе `Running`, порт 18080 проброшен на хост (см. рисунок Docker Desktop).

### 5. Размер контейнера до и после оптимизации

Для объективной оценки эффекта оптимизации собраны три варианта образа: «наивная» одностадийная сборка (`Dockerfile.naive`), исходный multi-stage из ЛР №4 и оптимизированный multi-stage из ЛР №5.

| Версия образа | Сборка | Размер | Сэкономлено |
|---|---|---|---|
| `promo_notify:naive` | Одностадийная сборка, тулчейн в финальном образе | **834 MB** | — (baseline) |
| `promo_notify:before` | Multi-stage (состояние до ЛР №5) | **96.1 MB** | −737.9 MB (−88.5 %) |
| `promo_notify:after` | Multi-stage + `--no-install-recommends` + `strip` + чистка `/usr/share` + удаление `promo_tests` | **92.4 MB** | −741.6 MB (−88.9 %) от baseline; **−3.7 MB (−3.8 %)** относительно `before` |

Команды для воспроизведения замеров:

```bash
docker build -f Dockerfile.naive -t promo_notify:naive .
docker build -t promo_notify:after .
docker images promo_notify --format 'table {{.Repository}}:{{.Tag}}\t{{.Size}}'
```

Распределение по слоям оптимизированного образа:

| Слой | Размер |
|---|---|
| `ubuntu:22.04` (база) | 78.1 MB |
| Установка runtime-библиотек (boost, curl, sqlite3) | ~13.6 MB |
| Бинарник `/app/promo_notify` (после `strip`) | ~0.6 MB |

### Выводы

1. Прототип доработан под три новых бизнес-требования: введён эндпоинт `GET /stats` (агрегат + JSON-ответ), CLI-режим `--stats` и одновременный вывод сводки **прямо в терминал сервера**. Сводка показывает разбивку по акциям, со списком отправленных номеров и номеров, на которые отправка не пошла из-за выключенных уведомлений.
2. Реализована полноценная Docker-упаковка с multi-stage сборкой и отдельной стадией `tester` для unit-тестов.
3. Применены классические приёмы оптимизации образа: `--no-install-recommends`, `strip`, удаление документации/локалей, исключение тестового бинарника из runtime, `.dockerignore`. Итоговый размер образа — **92.4 MB**, что в **9 раз меньше** «наивной» одностадийной сборки и на 3.8 % меньше Multi-stage до оптимизации.
4. Регрессии не обнаружено — все 7 unit-тестов из ЛР №4 проходят.
